# Проверка «Ход времени»

Дата: 29 октября 2026, Москва. Проверялось локальное приложение на `http://127.0.0.1:4173/`, обслуживающее production-каталог `dist`.

## Окружение и итог

- Node.js 22.23.3, npm 10.9.9; Google Chrome 155.0.8059.79 headless, Playwright 1.64.1.
- Настоящий WebGL 2 через ANGLE / Vulkan SwiftShader. Исходный viewport 1440×1000 CSS px, DPR 1; мобильная эмуляция 390×844, DPR 1, отдельный контекст с `hasTouch` и `isMobile`.
- `npm test`: **24/24**, три файла, последний прогон **717 ms**. Проверены endpoints, clamp/ranges, slerp и negative-dot/antipodal случаи, нормализация, finite values, отсутствие дрейфа, все 47 реальных деталей, единственный RAF, пауза, ручное прерывание, пропорциональная длительность и reduced motion. Кадры 0/100/1600/4500/10000 ms подтверждают зависимость от wall-clock; скрытая вкладка останавливает переход.
- `npm run build`: **успешно**, TypeScript и production Vite; финальная сборка без предупреждений. Финальный entry — `index-Bi65FQsc.js`.
- `npm run verify:model`: **пройдено**. GLB 3 020 672 bytes; 47 самостоятельных деталей, 95 узлов, 47 meshes, 101 primitive, 120 704 треугольника. Имена и rest-TRS совпадают с манифестом; quaternion нормализованы, геометрия непустая; внешних ресурсов, камер и источников света в GLB нет. [JSON проверки модели](evidence/model-validation.json).
- Все проверенные текстовые сочетания проходят 4.5:1: минимум **6.34:1** на панели; основной текст на фоне **15.70:1**. [Расчёт контраста](evidence/contrast.json).
- В нормальном режиме production **console.error/warning — 0**, неперехваченных ошибок и HTTP-ошибок нет; движение slider не перезагружает GLB. [Реальный renderer и console](evidence/browser-environment.json).

## Браузерные сценарии

Итог: **10 сценариев проверены успешно**. Это сводка двух прогонов: шесть неизменённых сценариев прошли в первом; после исправлений повторены четыре затронутых/незавершённых. Это не заявление об одном новом полном десятисценарном прогоне.

В первом прогоне обнаружены два дефекта: ограничение delta до 64 ms растягивало автоанимацию на медленном software renderer, а декоративная орбита расширяла документ до 381 px при viewport 360 px. Исправлены абсолютным elapsed wall-clock и локальным `overflow: clip` сцены. Оба исправления прошли целевой повтор.

## Адаптивность, масштаб и доступность

Проверены 320×740, 360×800, 390×844, 768×1024, 1280×800, 1440×900 и 1920×1080 CSS px. Progress сохраняется после resize; горизонтального скролла нет, ширина slider больше 200 px. Touch-контекст проверен отдельным реальным касанием через Playwright.

Масштаб 200% проверен **эмуляцией плотности**: 720×500 CSS px при DPR 2, эквивалентной 1440×1000 при увеличении. Это не управление нативной настройкой zoom браузера. `scrollWidth = 720`, slider доступен, его область 300×44 px, значение 100% сохранено. [Метрики](evidence/zoom-200.json), [скриншот](evidence/zoom-200.png).

В самой последней сборке отдельно выполнен быстрый DOM check с намеренно отключённым WebGL: `<output aria-live="off">`, ровно один live-region информации о детали, один coarse stage-status, язык `ru`, slider отключён, fallback действительно загружен. [Доказательство финальной семантической правки](evidence/final-a11y-dom.json). Визуальная геометрия этим атрибутом не меняется.

## Практические пределы проверки

Физические iPhone/Android, Safari/Firefox и реальные screen reader не использовались. Проверены Chrome headless, мобильные viewport/touch и DOM-семантика. Частота кадров на физических устройствах не измерялась. Software SwiftShader заметно медленнее аппаратного WebGL; адаптивный DPR снижает нагрузку, а длительность автоанимации теперь не накапливает задержку по числу кадров.

Модель авторская демонстрационная; инженерная точность исторического механизма не заявляется. Сведения о Blender MCP и доступности инструментов текущей AI-сессии приведены отдельно в [SETUP_REPORT.md](../SETUP_REPORT.md) и [BLENDER_MCP.md](BLENDER_MCP.md).
